# OpenPPP2 Windows WFP NAT66 (optional advanced backend)

This directory contains the optional signed-data-plane package source for
transparent Windows NAT66.  The default Windows server path does **not**
require this driver: it uses the existing user-mode IPv6 transit path, aligned
with the IPv4 backend, and is intended for virtual-subnet/client-to-client
forwarding.  Install and enable this package only when transparent uplink
NAT66 is explicitly needed.
The callout runs in kernel mode at `FWPM_LAYER_IPFORWARD_V6`; the desktop
server only supplies the transit/uplink interface indices, ULA prefix and the
current global uplink address through a restricted device IOCTL.

## Package flow

1. Install the Windows Driver Kit (WDK) matching the target Windows SDK.
2. Build `OpenPpp2WfpNat66.vcxproj` for `x64` or `ARM64`.
3. Sign the `.sys` and generated `.cat` with the organization certificate:

   ```powershell
   .\tools\sign-openppp2-wfp.ps1 -CertificateThumbprint <thumbprint> -Platform x64
   ```

4. Install the signed package as Administrator:

   ```powershell
   pnputil /add-driver .\bin\wfp\x64\OpenPpp2WfpNat66.inf /install
   ```

The script refuses to proceed without `msbuild.exe`, `inf2cat.exe`,
`signtool.exe`, and the requested certificate. No development or fake
signature is generated by this repository. Production Windows requires the
normal Microsoft driver-signing policy for the target release.

## Runtime contract

The application opens `\\.\OpenPpp2WfpNat66` only as an Administrator/System
process. The driver device ACL grants access to `SYSTEM` and local
Administrators; ordinary users cannot reconfigure the NAT callout.

`PrepareServerEnvironment` configures the driver and fails with
`IPv6Nat66Unavailable` if the signed package is missing or rejects the
configuration. `FinalizeServerEnvironment` sends the clear IOCTL, flushes flow
state, and leaves unrelated WFP rules untouched.

The v1 implementation deliberately fails closed for all IPv6 fragment groups
(including the first fragment),
unsupported extension headers, ICMPv6 messages without a stable echo-id key,
non-contiguous NBLs and malformed packets. WDK build, Driver Verifier, MTU/
fragment, uplink-address rotation, suspend/resume and x64/ARM64 end-to-end
tests are release gates and are not claimed by the source-only workspace.
